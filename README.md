# Build and Clean Scripts for Autotools Projects

This repository contains a set of shell scripts to help automate the building and cleaning of projects that use Autotools.

## Scripts

### `shell/buildautotools.sh`

This script automates the common sequence of commands to configure and build an Autotools-based project. It runs:
1.  `aclocal`
2.  `libtoolize --force`
3.  `autoconf`
4.  `autoheader`
5.  `automake --add-missing`
6.  `./configure [args...]`
7.  `make [args...]`

**Usage:**

```bash
./shell/buildautotools.sh [configure_and_make_args...]
```

Any arguments passed to `buildautotools.sh` will be passed to both the `./configure` command and the `make` command.

**Example:**

```bash
./shell/buildautotools.sh --prefix=/usr/local CFLAGS="-O2 -pipe" -j4
```
This will run `./configure --prefix=/usr/local CFLAGS="-O2 -pipe" -j4` and then `make --prefix=/usr/local CFLAGS="-O2 -pipe" -j4`.

The script includes error handling and will exit immediately if any command fails. It also uses `set -xv` for verbose output.

### `shell/cleanautotools.sh`

This script cleans up files generated by Autotools and the build process. It primarily relies on:
1.  `make clean`
2.  `make distclean`

It then attempts to remove a few common leftover files and directories that `make distclean` might not always remove, such as `aclocal.m4` and `autom4te.cache/`.

**Usage:**

```bash
./shell/cleanautotools.sh
```

The script includes error handling for the `make` commands and uses `set -xv` for verbose output. It no longer creates backups of `configure.ac` or `Makefile.am`, as version control (like Git) is the recommended way to manage file history.

## Prerequisites

To use these scripts, you need to have the following tools installed:
*   GNU Autotools ( `autoconf`, `automake`, `aclocal`, `autoheader`)
*   Libtool (`libtoolize`)
*   Make (`make`)
*   A C/C++ compiler (e.g., GCC) if you are building C/C++ projects.

These scripts are intended to be run from the root directory of an Autotools-based project.
